## Project overview

**energy-sim** (working title) - A free public website where a homeowner in England compares whole-house energy setups side by side, with cost, carbon and payback shown as honest ranges.

**Core workflow:**
1. Describe the house: postcode, house type, age band, size, then quick facts (insulation, glazing, heating, occupants)
2. Pick setups to compare: gas boiler or heat pump, with or without solar, on a chosen tariff
3. See each setup's annual cost, carbon and payback as ranges, side by side
4. Open any number to see its source, range and last-checked date

**Full specification:** [project-outline.md](./SPECIFICATIONS/ORIGINAL_IDEA/project-outline.md) (model and data detail in [home-energy-simulator-spec.md](./SPECIFICATIONS/ORIGINAL_IDEA/home-energy-simulator-spec.md))

## Architecture overview

**Stack:**
- **Language**: TypeScript 7 (strict), Node 24 LTS (pinned in `.nvmrc`)
- **Engine**: pure TypeScript library with no I/O; the register is validated with Zod ([register.md](./REFERENCE/register.md))
- **Testing**: Vitest with V8 coverage; Oxlint with type-aware rules; GitHub Actions CI ([ci.yml](./.github/workflows/ci.yml))
- **Scripts**: TypeScript run with `tsx`, in `scripts/`
- **Data**: build-time snapshots committed as JSON; no runtime external API calls
- **Web framework and styling**: TBD in phase 3
- **Database**: none planned (fully client-side, nothing personal stored)
- **Deployment**: Cloudflare (planned for phase 3)
- **Domain**: TBD

**Key Integrations** (all fetched at build time, never from the browser):
- PVGIS (EU JRC): hourly typical-year weather and solar
- Ofgem price cap; Octopus public tariff API (phase 2)
- NESO carbon intensity API (deferred beyond v1; v1 uses an annual grid carbon factor)

**Current Status:** Phase 2 spec written and reviewed; implementation not started. Phase 1 complete (closed 18 October 2026; spec archived). Tooling, CI, the benchmark ([scripts/benchmark/](./scripts/benchmark/README.md)), the register ([register.md](./REFERENCE/register.md)), the hourly engine, and the seeded sampling, paired comparison and sensitivity table ([engine.md](./REFERENCE/engine.md)) are done. The [phase 1 report](./reports/phase-1-london-semi.md) is generated by `npm run report`.

## TypeScript configuration

Configured in [tsconfig.json](./tsconfig.json):
- Strict mode, plus `noUncheckedIndexedAccess`
- ES2024 target, `nodenext` modules, `"type": "module"` in package.json
- No emit: `tsc` only type-checks. Code runs through `tsx` and Vitest, so imports use `.ts` extensions
- Types: Node only; browser types are added in phase 3
- TypeScript is pinned to an exact version and upgraded together with `oxlint-tsgolint` (see the [TypeScript 7 and Oxlint ADR](./REFERENCE/decisions/2026-10-17-typescript-7-with-oxlint.md))

## Testing

Tests serve dual purpose:
1. **Validation** - Verify code works
2. **Directional Context** - Guide AI development

**Commands:**
```bash
npm ci                    # Install the exact locked dependencies
npm test                  # Run all tests
npm run test:watch        # Watch mode
npm run test:coverage     # Tests with coverage thresholds (as CI runs them)
npm run typecheck         # TypeScript type check
npm run lint              # Oxlint, including type-aware rules
npm run benchmark:rough   # Benchmark step 1: rough heat-demand estimate
npm run benchmark:hem-input  # Benchmark step 2: write the HEM input files
npm run benchmark:tables     # Benchmark steps 2–3: print the comparison tables
npm run fetch:pvgis          # Re-fetch the PVGIS London snapshot (network; commit the result)
npm run calibrate            # Solve the mean internal temperature for the NEED gas target
npm run report               # Write reports/phase-1-london-semi.md (offline; commit it, CI checks drift)
npm run bench                # Time 500 samples × 2 setups; fails above 5 seconds
```

Tests sit next to the code they test (`*.test.ts`), as the phase 1 spec lays out.

**Coverage target:** 100% (enforced minimums: 95% lines/functions/statements, 90% branches)

**See:** [testing-strategy.md](./REFERENCE/testing-strategy.md) for complete details

## Project-specific notes

- **Every engine number comes from the register.** Every fact about houses, energy, prices or behaviour is a register row. Only physical constants and method settings (such as the report's seed and sample count, or algorithm coefficients) live in code. See the [register ADR](./REFERENCE/decisions/2026-10-17-typed-parameter-register.md).
- **No runtime external calls and no personal data on a server.** PVGIS forbids browser calls; data is snapshotted at build time. See the [client-side ADR](./REFERENCE/decisions/2026-10-17-client-side-build-time-snapshots.md).
- **Neutrality:** results are never influenced by commercial relationships.
- **Not advice:** the site gives estimates, not financial advice, and must say so.
- **Beta launch, validation later.** The site launches as a public beta to show proof of concept. Volunteer homes, expert review and other external validation follow the launch; they never gate a phase or the launch.
- **Brand-neutral** until Magnus has agreed any char.gy involvement with his employer.
- **New releases wait 14 days.** Dependabot holds version updates until a release is 14 days old; its security updates are not delayed. By hand, install with `npm install --before "$(date -v-14d +%F)" <package>`, which applies the limit to the whole dependency tree. For a GitHub Action, check the release date with `gh release view <tag> -R <owner/repo>` before pinning its SHA. A release that fixes a known vulnerability affecting us may skip the wait. See the [dependency wait ADR](./REFERENCE/decisions/2026-10-18-fourteen-day-dependency-wait.md).
